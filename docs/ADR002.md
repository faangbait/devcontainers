# ADR002: Devcontainer configuration inheritance

## Status

Accepted.

## Context

Each devcontainer variant (`.devcontainer-agents`, `.devcontainer-python`,
`.devcontainer-django`, `.devcontainer-rust`, ...) needs most of the settings
defined by the variants above it, plus a handful of its own overrides (build
target, `containerEnv`, `features`, `mounts`). Duplicating a full
`devcontainer.json` per variant would let them drift out of sync silently. A
single flat file covering every variant would make it impossible to tell what
a given variant actually contains.

## Decision

`src/configuration-inheritance.jsonc` declares a DAG of layers, each pointing
at its parent layer(s):

```
.devcontainer             (root, no parents)
.devcontainer-agents       -> .devcontainer
.devcontainer-agentic-unit -> .devcontainer-agents
.devcontainer-devops       -> .devcontainer-agents
.devcontainer-go           -> .devcontainer-agents
.devcontainer-rust         -> .devcontainer-agents
.devcontainer-typescript   -> .devcontainer-agents
.devcontainer-python       -> .devcontainer-agents
.devcontainer-django       -> .devcontainer-python
```

`src/merge-devcontainer.py` composes a leaf's final `devcontainer.json`:

1. Parses each layer's `devcontainer.json`/`.devcontainer.json` as JSONC.
   Python's stdlib `json` module accepts neither comments nor trailing
   commas, so `parse_jsonc` strips both by hand before delegating to
   `json.loads`.
2. Linearizes the DAG from the target layer up to its roots via a
   depth-first topological visit (`linearize`). A shared ancestor is only
   visited once; a layer revisited while still active on the traversal
   stack is a cycle and raises immediately rather than looping.
3. Merges layers left-to-right — most distant ancestor first, target layer
   last (`merge`): dicts merge key-by-key recursively, lists concatenate
   with the parent's items first, and any other type is replaced outright
   by the child's value.
4. Before folding in each next layer, strips any `nonInheritable` paths from
   the result so far (`remove_path`), so a value a parent defines doesn't
   automatically propagate to every descendant. A layer that redefines a
   stripped path for itself still gets its own value — the strip only
   blocks inheritance, not the owning layer's declaration.

`main()` also exposes `--self-test`, which exercises `merge`, `remove_path`,
and `linearize` against fixed inputs — there's no separate test file for
this script.

## Consequences

- A variant's `devcontainer.json` only needs to state what's different about
  it; everything else is inherited and stays in sync with its parents by
  construction rather than by convention.
- The inheritance graph is explicit and machine-checked: an unknown layer or
  a cycle fails composition instead of producing a wrong merged config.
- List-valued settings (`mounts`, VS Code `extensions`, etc.) accumulate down
  the chain instead of being replaced, so a child can add to a parent's
  mounts/extensions but can't silently drop them.
- Adding a new variant means one entry in `configuration-inheritance.jsonc`
  plus a `devcontainer.json` containing only its deltas, not a copy of an
  existing variant.
- `nonInheritable` exists specifically so a parent-layer secret or
  environment value doesn't leak into every descendant by default; it's
  currently unused (the field is empty with a commented-out example) but is
  load-bearing infrastructure for the day a layer needs a value that must
  not inherit.
